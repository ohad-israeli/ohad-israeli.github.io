## The business need

Every business runs on a stream of events: orders, payments, clicks, shipments, sensor readings. But a raw event is thin. An order tells you *customer 4821 bought SKU 12 for $89*. To act the moment it happens, you need live context that lives somewhere else:

- greet a **high-value customer** differently, using their loyalty tier and lifetime value;
- flag a **risky transaction** with a current risk score;
- promise an **accurate delivery date** from current inventory.

Doing that in real time has traditionally meant building and running a stream-processing application: consumers, calls to internal services, state, retries, schema changes, and a pager. Every new enrichment is another service to own, so most teams fall back to a nightly batch, and the moment to act has passed. Often the context sits behind an **internal API with no public endpoint**, which makes it harder still.

## Who this helps

- **Product and business owners** who want decisions made on the event, not the next morning.
- **Data and platform teams** tired of owning one more enrichment service.
- **Security teams** who need customer data to stay off the public internet.
- **Architects** looking for a pattern that scales to fraud scoring, pricing, logistics and customer 360.

## The approach

On Confluent Cloud the enrichment is declarative. Events already flow through Kafka. A **Flink SQL** statement looks up each event's customer in the internal API and attaches the result, and Confluent runs it with no application to build or operate. Flink reaches the private API over **AWS Egress PrivateLink**, so the call never touches the public internet.

## Things to pay attention to

**1. Who connects to whom.** For a private API, the direction is the opposite of what many expect. *You* publish the API as an AWS VPC Endpoint Service, and *you authorize Confluent's egress gateway* to connect to it. Its role is to keep the whole path private: Confluent attaches an endpoint, and a DNS record maps your API's hostname to it.

**2. Where Flink can do this.** Egress private connectivity for Flink is available on AWS and Azure. On Google Cloud, [egress Private Service Connect](https://docs.confluent.io/cloud/current/networking/gcp-egress-psc.html) is limited to fully managed connectors. Choose the cloud for the Flink side with that in mind.

**3. HTTPS with a valid certificate.** Flink's REST connection requires `https://`. Its role is to protect the call end to end, so the private endpoint needs a normal TLS certificate, with a bearer token on top.

## Summary

- **Thin events become decisions** when each one is enriched in flight, not in a nightly batch.
- **A private API is not a blocker.** Flink SQL reaches it over PrivateLink with no pipeline code.
- **What we ran:** per-event lookups for four customer keys against a private Customer-360 API over PrivateLink, returning tier, lifetime value and status for each.
