Every real-time enrichment pipeline usually ends the same way: spinning up a custom consumer
microservice just to call an internal REST API, handle retries, and write the result back to
Kafka. With Confluent Cloud for Apache Flink and AWS Egress PrivateLink, you can replace that
service entirely, querying private, internal endpoints per event using nothing but three SQL
statements.

This is the technical deep-dive behind
[Your Event Stream Is Missing Half the Story](/projects/real-time-stream-enrichment), which
makes the business case. Here is how it works, enriching an order stream with live data from a
**private** Customer-360 API.

## The shape of it

Orders arrive on a topic. For each order, Flink looks up the customer in an **internal
Customer-360 API that has no public endpoint**, because it lives privately inside the
company's own cloud network, and attaches the loyalty tier, lifetime value and status. No
consumer app and no service to run.

## Statements 1 and 2: turn the API into a table

A **connection** holds the secured endpoint, and an **external table** maps the API's JSON
response to columns Flink SQL can query:

```sql
-- 1. The private API as a secured Flink connection (HTTPS + bearer token):
CREATE CONNECTION customer_api WITH (
  'type'     = 'rest',
  'endpoint' = 'https://customer-api.internal.example/customers',
  'token'    = '<bearer-token>'
);

-- 2. An external table over that connection: the first column is the request key,
--    the rest map to the JSON response fields.
CREATE TABLE customer_lookup (
  customer_id    STRING,
  customer_name  STRING,
  account_tier   STRING,
  lifetime_value DOUBLE,
  is_active      BOOLEAN
) WITH (
  'connector'       = 'rest',
  'rest.connection' = 'customer_api',
  'rest.method'     = 'GET'
);
```

The connection keeps the credential out of the query. The table gives the API a schema, so
the rest of your SQL treats it like any other source.

## Statement 3: the per-event lookup

**`KEY_SEARCH_AGG`** does a key lookup against that table for each row: an asynchronous,
batched, retrying call to the API for each event, without a line of imperative code:

```sql
SELECT o.order_id, o.product, o.amount,
       c.customer_name, c.account_tier, c.lifetime_value
FROM orders AS o,
LATERAL TABLE(KEY_SEARCH_AGG(customer_lookup, DESCRIPTOR(customer_id), o.customer_id));
```

Against the demo's Customer-360 service, the lookup returned live data per key. The API was
called privately, over PrivateLink, for each row:

```text
customer_id  customer_name   account_tier  lifetime_value  is_active
1            Customer 1      PLATINUM       4273.15         true
2            Customer 2      SILVER         1648.61         true
42           Customer 42     SILVER          943.53         true
7            Customer 7      SILVER          194.49         true
```

## Things to pay attention to: reaching a private endpoint

The API is private, so Flink reaches it over **AWS Egress PrivateLink**. Three details decide
whether it works:

1. **The direction.** *You* publish your API as an **AWS VPC Endpoint Service**, fronted by
   an internal NLB, and **authorize Confluent's egress gateway** (its `principal_arn`) to
   connect to it. This is the reverse of inbound PrivateLink.
2. **DNS.** Confluent attaches a private endpoint and a **DNS record** maps your API's
   hostname to it, so Flink resolves that hostname to the private endpoint instead of the
   public internet.
3. **HTTPS with a valid certificate.** The REST connection requires `https://`, so the
   endpoint is served with a normal TLS certificate. The bearer token then locks it down at
   the application layer, on top of the private network.

Flink egress private connectivity is available on AWS and Azure. On Google Cloud, egress
Private Service Connect is limited to fully managed connectors. The Terraform for the
gateway, access point, DNS record and endpoint service is in the repo.

## Summary

- **Three statements** (connection, external table, lookup) make a private REST API a
  first-class Flink SQL source.
- **`KEY_SEARCH_AGG`** replaces a consumer app: async, batched, retrying, per event.
- **PrivateLink direction, DNS and HTTPS** are the details that decide whether the private
  path works.
- **What we ran:** the connection and external table created successfully, and a per-key
  lookup returned tier, lifetime value and status for four customers over PrivateLink.

Full Terraform, SQL and the mock API are in the
[repo](https://github.com/ohad-israeli/flink-private-api-enrichment).
